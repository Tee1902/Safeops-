# SAFEOPS -- THIẾT KẾ CƠ SỞ DỮ LIỆU (BE2)

> Tài liệu mô tả phiên bản trước tích hợp. Xem [backend/README.md](backend/README.md) và [báo cáo tích hợp](backend/docs/INTEGRATION.md) cho code/API/schema hiện hành.

**Phiên bản:** 1.1 -- Bản đề xuất để thống nhất với nhóm
**Công nghệ:** PostgreSQL, NestJS, TypeORM
**Phạm vi:** 8 bảng dữ liệu cốt lõi

## 1. Bảng `roles` -- Vai trò

  Trường          Kiểu dữ liệu   Ràng buộc                              Ý nghĩa
  --------------- -------------- -------------------------------------- ----------------------
  `id`            INT            PK, GENERATED BY DEFAULT AS IDENTITY   Mã vai trò
  `code`          VARCHAR(50)    UNIQUE, NOT NULL                       Mã định danh vai trò
  `name`          VARCHAR(100)   NOT NULL                               Tên vai trò
  `description`   TEXT           NULL                                   Mô tả vai trò
  `created_at`    TIMESTAMPTZ    NOT NULL, DEFAULT NOW()                Ngày tạo

**Các vai trò dự kiến**

  `code`       `name`              Ý nghĩa
  ------------ ------------------- -----------------------------------------
  `ADMIN`      Quản trị viên       Quản trị tài khoản và cấu hình hệ thống
  `MANAGER`    Quản lý             Theo dõi, xác minh và phân công sự cố
  `REPORTER`   Người báo cáo       Tạo và theo dõi sự cố
  `SECURITY`   Nhân viên an ninh   Tiếp nhận và xử lý sự cố

                                                           diện

## 3. Bảng `incident_types` -- Loại sự cố

  -----------------------------------------------------------------------
  Trường            Kiểu dữ liệu      Ràng buộc         Ý nghĩa
  ----------------- ----------------- ----------------- -----------------
  `id`              INT               PK, GENERATED BY  Mã loại sự cố
                                      DEFAULT AS        
                                      IDENTITY          

  `code`            VARCHAR(50)       UNIQUE, NOT NULL  Mã định danh loại
                                                        sự cố

  `name`            VARCHAR(100)      NOT NULL          Tên loại sự cố

  `description`     TEXT              NULL              Mô tả loại sự cố

  `icon`            VARCHAR(100)      NULL              Tên hoặc mã biểu
                                                        tượng hiển thị

  `is_active`       BOOLEAN           NOT NULL, DEFAULT Loại sự cố có
                                      TRUE              đang được sử dụng

  `created_at`      TIMESTAMPTZ       NOT NULL, DEFAULT Ngày tạo
                                      NOW()             

  `updated_at`      TIMESTAMPTZ       NOT NULL, DEFAULT Ngày cập nhật
                                      NOW()             
  -----------------------------------------------------------------------

**Ví dụ loại sự cố dự kiến:** `FIRE` (cháy nổ), `ACCIDENT` (tai nạn),
`THEFT` (trộm cắp), `MEDICAL` (y tế), `OTHER` (khác). Nhóm cần thống
nhất danh sách cuối cùng.

## 4. Bảng `incidents` -- Sự cố

  --------------------------------------------------------------------------------
  Trường               Kiểu dữ liệu      Ràng buộc               Ý nghĩa
  -------------------- ----------------- ----------------------- -----------------
  `id`                 UUID              PK, DEFAULT             Mã sự cố
                                         gen_random_uuid()       

  `title`              VARCHAR(200)      NOT NULL                Tiêu đề sự cố

  `description`        TEXT              NOT NULL                Nội dung mô tả sự
                                                                 cố

  `incident_type_id`   INT               FK →                    Loại sự cố
                                         `incident_types(id)`,   
                                         NOT NULL                

  `reporter_id`        UUID              FK → `users(id)`, NOT   Người tạo báo cáo
                                         NULL                    sự cố

  `verified_by`        UUID              FK → `users(id)`, NULL  Người xác minh sự
                                                                 cố

  `latitude`           NUMERIC(10,7)     NOT NULL, CHECK         Vĩ độ vị trí xảy
                                         (BETWEEN -90 AND 90)    ra sự cố

  `longitude`          NUMERIC(10,7)     NOT NULL, CHECK         Kinh độ vị trí
                                         (BETWEEN -180 AND 180)  xảy ra sự cố

  `address`            TEXT              NULL                    Địa chỉ hoặc mô
                                                                 tả vị trí

  `severity`           VARCHAR(20)       NOT NULL, DEFAULT       Mức độ nghiêm
                                         'MEDIUM', CHECK theo    trọng
                                         danh sách mức độ        

  `status`             VARCHAR(30)       NOT NULL, DEFAULT       Trạng thái xử lý
                                         'PENDING', CHECK theo   sự cố
                                         danh sách trạng thái    

  `rejection_reason`   TEXT              NULL                    Lý do từ chối sự
                                                                 cố

  `verified_at`        TIMESTAMPTZ       NULL                    Thời điểm xác
                                                                 minh

  `created_at`         TIMESTAMPTZ       NOT NULL, DEFAULT NOW() Thời điểm tạo báo
                                                                 cáo

  `updated_at`         TIMESTAMPTZ       NOT NULL, DEFAULT NOW() Thời điểm cập
                                                                 nhật

  `resolved_at`        TIMESTAMPTZ       NULL                    Thời điểm xử lý
                                                                 hoàn tất
  --------------------------------------------------------------------------------

**Giá trị đề xuất cho `severity`**

  Giá trị      Ý nghĩa
  ------------ ------------
  `LOW`        Thấp
  `MEDIUM`     Trung bình
  `HIGH`       Cao
  `CRITICAL`   Khẩn cấp

**Giá trị đề xuất cho `status`**

  Giá trị         Ý nghĩa
  --------------- ---------------
  `PENDING`       Chờ xác minh
  `VERIFIED`      Đã xác minh
  `REJECTED`      Đã từ chối
  `ASSIGNED`      Đã phân công
  `IN_PROGRESS`   Đang xử lý
  `RESOLVED`      Đã xử lý xong
  `CLOSED`        Đã đóng

## 5. Bảng `incident_attachments` -- Tệp đính kèm sự cố

  -------------------------------------------------------------------------
  Trường            Kiểu dữ liệu      Ràng buộc           Ý nghĩa
  ----------------- ----------------- ------------------- -----------------
  `id`              UUID              PK, DEFAULT         Mã tệp đính kèm
                                      gen_random_uuid()   

  `incident_id`     UUID              FK →                Sự cố chứa tệp
                                      `incidents(id)`,    đính kèm
                                      NOT NULL            

  `uploaded_by`     UUID              FK → `users(id)`,   Người tải tệp lên
                                      NOT NULL            

  `file_name`       VARCHAR(255)      NOT NULL            Tên tệp

  `file_url`        TEXT              NOT NULL            Đường dẫn hoặc
                                                          storage key của
                                                          tệp

  `file_type`       VARCHAR(100)      NOT NULL            Loại tệp hoặc
                                                          MIME type

  `file_size`       BIGINT            NOT NULL, CHECK     Dung lượng tệp
                                      (file_size \> 0)    tính bằng byte

  `created_at`      TIMESTAMPTZ       NOT NULL, DEFAULT   Thời điểm tải tệp
                                      NOW()               lên
  -------------------------------------------------------------------------

## 6. Bảng `assignments` -- Phân công xử lý sự cố

  ----------------------------------------------------------------------------
  Trường               Kiểu dữ liệu      Ràng buộc           Ý nghĩa
  -------------------- ----------------- ------------------- -----------------
  `id`                 UUID              PK, DEFAULT         Mã phân công
                                         gen_random_uuid()   

  `incident_id`        UUID              FK →                Sự cố được phân
                                         `incidents(id)`,    công
                                         NOT NULL            

  `security_user_id`   UUID              FK → `users(id)`,   Nhân viên an ninh
                                         NOT NULL            được giao

  `assigned_by`        UUID              FK → `users(id)`,   Người thực hiện
                                         NOT NULL            phân công

  `note`               TEXT              NULL                Ghi chú phân công

  `status`             VARCHAR(30)       NOT NULL, DEFAULT   Trạng thái phân
                                         'ASSIGNED', CHECK   công
                                         theo danh sách      
                                         trạng thái          

  `assigned_at`        TIMESTAMPTZ       NOT NULL, DEFAULT   Thời điểm phân
                                         NOW()               công

  `accepted_at`        TIMESTAMPTZ       NULL                Thời điểm nhân
                                                             viên tiếp nhận

  `started_at`         TIMESTAMPTZ       NULL                Thời điểm bắt đầu
                                                             xử lý

  `completed_at`       TIMESTAMPTZ       NULL                Thời điểm hoàn
                                                             thành xử lý
  ----------------------------------------------------------------------------

**Giá trị đề xuất cho `status`**

  Giá trị         Ý nghĩa
  --------------- -------------------
  `ASSIGNED`      Đã được phân công
  `ACCEPTED`      Đã tiếp nhận
  `IN_PROGRESS`   Đang thực hiện
  `COMPLETED`     Đã hoàn thành
  `CANCELLED`     Đã hủy phân công

## 7. Bảng `incident_logs` -- Nhật ký sự cố

  -------------------------------------------------------------------------
  Trường            Kiểu dữ liệu      Ràng buộc           Ý nghĩa
  ----------------- ----------------- ------------------- -----------------
  `id`              UUID              PK, DEFAULT         Mã nhật ký
                                      gen_random_uuid()   

  `incident_id`     UUID              FK →                Sự cố được ghi
                                      `incidents(id)`,    nhật ký
                                      NOT NULL            

  `actor_id`        UUID              FK → `users(id)`,   Người thực hiện
                                      NULL                hành động; NULL
                                                          nếu do hệ thống

  `action`          VARCHAR(50)       NOT NULL            Mã hành động được
                                                          thực hiện

  `old_status`      VARCHAR(30)       NULL                Trạng thái trước
                                                          khi thay đổi

  `new_status`      VARCHAR(30)       NULL                Trạng thái sau
                                                          khi thay đổi

  `note`            TEXT              NULL                Nội dung ghi chú

  `metadata`        JSONB             NULL                Dữ liệu bổ sung
                                                          của hành động

  `created_at`      TIMESTAMPTZ       NOT NULL, DEFAULT   Thời điểm ghi
                                      NOW()               nhận nhật ký
  -------------------------------------------------------------------------

**Giá trị `action` đề xuất**

  Giá trị      Ý nghĩa
  ------------ --------------------
  `CREATED`    Tạo sự cố
  `VERIFIED`   Xác minh sự cố
  `REJECTED`   Từ chối sự cố
  `ASSIGNED`   Phân công xử lý
  `ACCEPTED`   Tiếp nhận xử lý
  `STARTED`    Bắt đầu xử lý
  `RESOLVED`   Hoàn thành xử lý
  `CLOSED`     Đóng sự cố
  `UPDATED`    Cập nhật thông tin

## 8. Bảng `notifications` -- Thông báo

  -------------------------------------------------------------------------
  Trường            Kiểu dữ liệu      Ràng buộc           Ý nghĩa
  ----------------- ----------------- ------------------- -----------------
  `id`              UUID              PK, DEFAULT         Mã thông báo
                                      gen_random_uuid()   

  `user_id`         UUID              FK → `users(id)`,   Người nhận thông
                                      NOT NULL            báo

  `incident_id`     UUID              FK →                Sự cố liên quan
                                      `incidents(id)`,    đến thông báo
                                      NULL                

  `type`            VARCHAR(50)       NOT NULL            Mã loại thông báo

  `title`           VARCHAR(200)      NOT NULL            Tiêu đề thông báo

  `message`         TEXT              NOT NULL            Nội dung thông
                                                          báo

  `is_read`         BOOLEAN           NOT NULL, DEFAULT   Trạng thái đã đọc
                                      FALSE               

  `read_at`         TIMESTAMPTZ       NULL                Thời điểm đọc
                                                          thông báo

  `created_at`      TIMESTAMPTZ       NOT NULL, DEFAULT   Thời điểm tạo
                                      NOW()               thông báo
  -------------------------------------------------------------------------

**Giá trị `type` đề xuất**

  Giá trị                Ý nghĩa
  ---------------------- --------------------------
  `INCIDENT_CREATED`     Có sự cố mới
  `INCIDENT_VERIFIED`    Sự cố đã được xác minh
  `INCIDENT_REJECTED`    Sự cố bị từ chối
  `ASSIGNMENT_CREATED`   Có phân công mới
  `ASSIGNMENT_UPDATED`   Phân công được cập nhật
  `INCIDENT_RESOLVED`    Sự cố đã được xử lý xong

## 9. Tổng hợp khóa ngoại

  --------------------------------------------------------------------------------------
  Bảng chứa FK             Trường khóa ngoại    Tham chiếu đến         Ý nghĩa
  ------------------------ -------------------- ---------------------- -----------------
  `users`                  `role_id`            `roles(id)`            Vai trò của người
                                                                       dùng

  `incidents`              `incident_type_id`   `incident_types(id)`   Loại sự cố

  `incidents`              `reporter_id`        `users(id)`            Người báo cáo

  `incidents`              `verified_by`        `users(id)`            Người xác minh

  `incident_attachments`   `incident_id`        `incidents(id)`        Sự cố có tệp đính
                                                                       kèm

  `incident_attachments`   `uploaded_by`        `users(id)`            Người tải tệp

  `assignments`            `incident_id`        `incidents(id)`        Sự cố được phân
                                                                       công

  `assignments`            `security_user_id`   `users(id)`            Nhân viên nhận
                                                                       phân công

  `assignments`            `assigned_by`        `users(id)`            Người phân công

  `incident_logs`          `incident_id`        `incidents(id)`        Sự cố có nhật ký

  `incident_logs`          `actor_id`           `users(id)`            Người thực hiện
                                                                       hành động

  `notifications`          `user_id`            `users(id)`            Người nhận thông
                                                                       báo

  `notifications`          `incident_id`        `incidents(id)`        Sự cố liên quan
  --------------------------------------------------------------------------------------

### Các điểm cần nhóm xác nhận

1.  Có thống nhất `users.id` là UUID và các khóa ngoại liên quan dùng
    UUID không?
2.  Có thống nhất bốn vai trò `ADMIN`, `MANAGER`, `REPORTER`, `SECURITY`
    không?
3.  Một sự cố có thể được phân công cho nhiều nhân viên cùng lúc không?
4.  Có thống nhất danh sách trạng thái sự cố và trạng thái phân công
    không?
5.  File được lưu ở đâu (local storage, MinIO, Cloudinary hoặc dịch vụ
    khác)?
6.  BE3 có đồng ý cấu trúc bảng `notifications` này không?
7.  Nhóm sử dụng PostgreSQL phiên bản 16 hay 17?
